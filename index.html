uwu.js is an small little reactive-dom library
it enables you to write reactive variables right in your .html page like this:
<uwu id="var_name">0</uwu>
reference them on any other tag like this:
<p _uwu="var_name"></p>
and then modify them anywhere in your .js code like this:
var_name++;
That's it.
No JSX. No state() setup. No frameworks. No virtual-DOM.
uwu.js works how you think it would by default.

What uwu do:

  1. define reactive variables straight in the DOM with the <uwu> tag
  2. reference reactive variables on any HTML tag with the _uwu attribute
  3. bind reactive variables to <input> tags, currently supporting:
    • text
    • numbers
    • checkboxes

What uwu don't do:

  • care about variable types
  • support custom components/nesting
  • run auto-updating js-code in the DOM
  • support persistent variable data

If you want those things, while still keeping your dependencies small, checkout DOMDOG. Written by the same folks, but with a few more fun things included.

Should i?

If you are building a super simple website, and you just want specific DOM parts to automatically update when specific variables change in value, then uwu is 4 u.

If you are building a slighter more complex website/webapp, you may want to look at DOMDOG.

If you are building a large app, with lots of moving parts, or maybe working with a big team that has unique needs, perhaps something like Vue or the wonderful SvelteKit is more your style.
